Best-Effort Algorithm

Sliding-window detection of personal best times over GPS distance/time streams — the same technique Strava uses for its own "Best Efforts" feature.

Data source: GPS streams

Strava exposes cumulative arrays for every activity via:

GET /activities/{id}/streams?keys=distance,time&key_by_type=true

The response contains two parallel arrays:

{
  "distance": { "data": [0.0, 10.5, 21.2, 31.8, ...] },
  "time":     { "data": [0, 1, 2, 3, ...] }
}
  • distance — cumulative metres from the activity start. Monotonically non-decreasing.
  • time — cumulative seconds from the activity start. Monotonically non-decreasing.
  • Both arrays are the same length; element k represents the state at GPS sample k.

strava_client.fetch_activity_streams(strava_id) wraps this call and returns {"distance": [...], "time": [...]}.

Algorithm — two-pointer sliding window

find_best_effort(distances, times, target_m) → float | None

Goal

Find the minimum value of times[j] − times[i] over all index pairs (i, j) where distances[j] − distances[i] ≥ target_m. This is the shortest elapsed time in which the athlete covered at least target_m metres continuously in a single activity.

Why two pointers?

A naïve O(n²) approach tries every (i, j) pair. Two pointers achieve O(n) by exploiting a key invariant of monotone arrays:

Invariant: the minimum valid j for i+1 is always ≥ the minimum valid j for i.

Proof: if distances[j] − distances[i] ≥ target_m and distances[i+1] ≥ distances[i], then distances[j] − distances[i+1] ≤ distances[j] − distances[i]. So the window shrinks as the left pointer advances — j may need to move further right but never left. It advances at most n times across the entire outer loop.

Step-by-step walkthrough

Target: 500 m

distances = [0,  100, 200, 300, 400, 500, 600, 700]   (metres, cumulative)
times     = [0,   20,  40,  60,  70,  80,  85,  90]   (seconds, cumulative)

i=0  advance j until distances[j] − 0 ≥ 500
     → j=5  (500 m)    elapsed = 80 − 0  = 80 s    best = 80

i=1  distances[5] − 100 = 400 < 500, advance j
     → j=6  (600 m)    elapsed = 85 − 20 = 65 s    best = 65

i=2  distances[6] − 200 = 400 < 500, advance j
     → j=7  (700 m)    elapsed = 90 − 40 = 50 s ★  best = 50

i=3  distances[7] − 300 = 400 < 500, advance j
     → j=8  = n        no valid right endpoint → break

Result: 50 s  (the fastest 500 m segment, between index 2 and index 7)

The early break is correct: once j reaches the end of the array without covering target_m, advancing i can only reduce distances[n-1] − distances[i], making it impossible to satisfy the constraint. No future i can produce a valid window.

Complexity

PropertyValue
Time O(n) — i advances n times; j advances at most n times total
Space O(1) extra — two pointers and one running minimum

Python implementation

def find_best_effort(
    distances: list[float],
    times: list[float],
    target_m: float,
) -> float | None:
    n = len(distances)
    if n < 2 or len(times) != n or target_m <= 0:
        return None

    best: float | None = None
    j = 0

    for i in range(n):
        if j <= i:
            j = i + 1                         # j must always lead i

        while j < n and distances[j] - distances[i] < target_m:
            j += 1                            # expand window right

        if j >= n:
            break                             # no valid window from here onward

        elapsed = times[j] - times[i]
        if best is None or elapsed < best:
            best = elapsed                    # new candidate best

    return best

BestEffort model

Each computed result is stored as a BestEffort row linked to the Activity it came from.

FieldTypeDescription
activityFK → ActivityThe activity in which the best was achieved
target_distance_mIntegerFieldTarget in metres (e.g. 5000)
elapsed_time_sFloatFieldFastest elapsed time in seconds
achieved_atDateFieldCalendar date of the activity
pace_per_kmFloatFieldDecimal minutes per kilometre

The pair (activity, target_distance_m) is unique — running the computation again is safe and will update existing rows rather than create duplicates.

Computed properties

effort.time_display   # → "21:34" or "1:05:12"
effort.pace_display   # → "4:19"  (M:SS per km)

How the Records page uses this

The Records & Streaks page queries the single best BestEffort per target distance across all activities, then links back to the source activity: 

best = (
    BestEffort.objects
    .filter(target_distance_m=5000)
    .select_related("activity")
    .order_by("elapsed_time_s")
    .first()
)

If no data exists for a target, the row is omitted and an empty-state prompt tells the user to run backfill_best_efforts.

Running the backfill

# Process all activities (one stream API call per activity)
python manage.py backfill_best_efforts

# Test with a small batch first
python manage.py backfill_best_efforts --limit 10

# Force-recompute even if BestEffort rows already exist
python manage.py backfill_best_efforts --force

Activities shorter than 1 K are skipped without an API call. The command is rate-aware: it sleeps 1 second between requests and pauses 15 minutes after every 80 calls to stay within Strava's 100-request/15-minute limit.

Going forward, sync_activities automatically computes best efforts for every newly-synced activity without requiring a separate command.
